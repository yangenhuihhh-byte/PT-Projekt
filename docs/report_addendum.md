# Report Addendum: Response to Supervisor Feedback

## 1. Generalization Evaluation

The original report only showed the prediction result of one microscope image. This is
not sufficient to demonstrate generalization. The revised evaluation therefore uses a
strict split by complete microscope images:

| Split | Sample groups | Number of complete images | Purpose |
|---|---:|---:|---|
| Training set | V1-V20 | 120 | Model fitting |
| Validation set | V21-V24 | 24 | Hyperparameter and epoch selection |
| Test set | V25-V29 | 30 | Final generalization analysis |

The split is performed before patch generation. This is important because adjacent
patches from the same microscope image are highly correlated. If patches were randomly
split, the test set could contain patches from images already used in training.

For the default 128 x 128 patch size and stride 128, this produces:

| Split | Complete images | Patches |
|---|---:|---:|
| Training set | 120 | 30,720 |
| Validation set | 24 | 6,144 |
| Test set | 30 | 7,680 |

The report should include both patch-level test metrics and complete-image test metrics.
Patch-level metrics are generated by:

```bash
python scripts/evaluate.py --model small_unet --checkpoint unet_patch128_ep100.pth --split test
```

Complete-image metrics are generated by:

```bash
python scripts/predict_full_image.py --model small_unet --checkpoint unet_patch128_ep100.pth --split test --patch-size 128 --stride 64 --blend gaussian
```

To report complete-image generalization instead of a single example only, run:

```bash
python scripts/predict_full_image.py --model small_unet --checkpoint models/small_unet_patch128_stride128_ep100_best.pth --split test --all-samples --patch-size 128 --stride 64 --blend gaussian
```

## 2. Meaning of MAE, MSE and RMSE

The values reported as MAE, MSE and RMSE are normalized errors. Before training and
evaluation, each height map is min-max normalized:

```text
h_norm = (h - h_min) / (h_max - h_min)
```

The error metrics are then calculated as:

```text
MAE_norm = mean(abs(h_pred_norm - h_true_norm))
MSE_norm = mean((h_pred_norm - h_true_norm)^2)
RMSE_norm = sqrt(MSE_norm)
```

Because both prediction and target are represented in the normalized range, values below
1 are expected. These metrics are dimensionless and do not directly represent micrometers.

Important implementation note: the earlier training script normalized the full height map
and then additionally standardized each patch target by its mean and standard deviation.
This made the interpretation of the saved checkpoint ambiguous. The revised scripts use a
single min-max normalization path for training, validation, testing and full-image
prediction. Final report metrics should therefore be generated from checkpoints trained
with the revised workflow.

The `.al3d` height files also contain header metadata. The revised loader reads the
`DepthImageOffset` field and removes the header-defined `InvalidPixelValue`
(`3.000000028082e+15` in the checked files) before normalization. This prevents invalid
pixels from dominating the min-max range.

For full-image prediction, raw-scale errors can also be reported by inverse scaling:

```text
h_pred_raw = h_pred_norm * (h_max - h_min) + h_min
```

The raw-scale values should be described as "raw height units" unless the exact physical
unit conversion is confirmed from the Alicona metadata. The normalized metrics are the
primary report metrics because every microscope image has a slightly different absolute
height interval.

## 5. Reducing Block Artifacts

The blocky or mosaic-like prediction is mainly caused by independent patch prediction and
hard patch boundaries. Three stitching strategies should be compared:

| Method | Patch size | Stride | Blending |
|---|---:|---:|---|
| No overlap | 128 | 128 | direct replacement |
| Overlap | 128 | 64 | uniform averaging |
| Overlap + Gaussian | 128 | 64 | center-weighted Gaussian kernel |

For Gaussian blending:

```text
H_pred = sum(w_i * P_i) / sum(w_i)
```

Here `P_i` is the prediction from one patch and `w_i` is the Gaussian weight map. The
patch center has higher weight and the border has lower weight, which reduces visible
seams between neighboring patches.

The revised report should include a small table comparing the three stitching settings
on the same complete test image:

| Stitching setting | Patch size | Stride | MAE_norm | MSE_norm | RMSE_norm |
|---|---:|---:|---:|---:|---:|
| No overlap | 128 | 128 | fill from `full_image_metrics.csv` | fill | fill |
| Uniform overlap | 128 | 64 | fill | fill | fill |
| Gaussian overlap | 128 | 64 | fill | fill | fill |

The visual comparison should discuss both quantitative error and the visible reduction of
block artifacts.

## 6. Transformer-Based Comparison

The project topic refers to transformer-based depth estimation. Therefore, U-Net should
be presented as a strong baseline rather than the only final model. The revised code
adds a lightweight TransUNet-style model:

```bash
python scripts/train.py --model transunet_lite --epochs 100 --patch-size 128 --stride 128
```

Recommended discussion:

- U-Net is suitable for dense prediction because the encoder captures context and the
  decoder with skip connections preserves localization.
- TransUNet extends this idea by using transformer attention to model long-range
  dependencies.
- Swin-Unet is another related transformer U-shaped architecture with shifted-window
  attention.
- Dense Prediction Transformer is especially relevant because height prediction is a
  dense prediction task.
